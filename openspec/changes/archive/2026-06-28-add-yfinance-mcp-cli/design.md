## Context

The repo already has an established two-surface pattern for data libraries, fully realized for AKShare (Chinese markets):

- **CLI harness** at `akshare-agent-harness/`: PEP 420 namespace package `cli_anything.akshare`, with `core/` (registry, models, database, runner, proxy), a Click CLI (`akshare_cli.py`) with REPL, a JSON registry mirrored into SQLite via a two-table (`functions` / `function_columns`) SQLAlchemy schema, `setup.py` installable as `cli-anything-yfinance`-style entry point, and pytest tests that skip when the underlying lib is absent.
- **MCP server** at `mcp/akshare-mcp/server.py`: FastMCP stdio, five tools (`search_functions`, `get_function_info`, `list_categories`, `list_functions`, `call_akshare_function`), own `pyproject.toml` + `.env`, registered in root `.mcp.json`.

yfinance is the natural global-market counterpart. Its API surface differs from akshare's: akshare exposes ~673 flat module-level functions, while yfinance centers on the `Ticker` object (methods like `history`, `info`, `financials`, `balance_sheet`, `holders`, `option_chain`, `calendar`) plus a few top-level functions (`download`, `search`, `Ticker`). The harness must normalize these into the same flat `command`-keyed registry the akshare pattern expects, so the CLI/MCP code can be near-identical.

## Goals / Non-Goals

**Goals:**
- A working `cli-anything-yfinance` CLI with `search`/`info`/`list`/`categories`/`call`/`repl`, behaviorally parallel to `cli-anything-akshare`.
- A working `yfinance-mcp` server exposing the same five-tool surface as `akshare-mcp`, with `call_yfinance_function` executing real yfinance calls.
- Curated registry (not exhaustive) covering the highest-value yfinance callables, categorized, with parameter + output-column metadata where useful.
- Maximal code reuse / parallel structure with akshare — a reader who knows one harness knows the other.

**Non-Goals:**
- Exhaustive coverage of every `Ticker` attribute/method (yfinance has dozens; we curate the useful subset).
- Writing into the unified `mcp/daas.db` or self-registering into `leader-mcp` (akshare-mcp does neither; we match it).
- A proxy layer. akshare's `proxy.py` exists because Chinese data sources need it; yfinance hits Yahoo directly and uses `requests` session caching natively. Skip the proxy module.
- Migration tooling from an upstream-generated registry. akshare's `registry.json` was generated by scraping akshare's docs; yfinance's API is stable and small enough to hand-curate as a Python dict / JSON.

## Decisions

**1. Normalize the `Ticker`-centric API into flat `command` names.**
yfinance groups calls under a `Ticker(symbol)` object. The registry needs flat, unique `command` keys (the akshare schema's natural key). Decision: register Ticker methods as `ticker_<method>` (e.g. `ticker_history`, `ticker_info`, `ticker_financials`) and top-level functions by their own name (`download`, `search`). The runner resolves the command: for `ticker_*` it constructs `yf.Ticker(symbol)` then calls the method; for top-level it calls `yf.<name>(**params)`.
- *Alternative*: expose each Ticker method as a separate tool with `symbol` baked into its name. Rejected — conflicts with the flat-registry pattern and breaks `search`/`list` symmetry with akshare.
- *Alternative*: model `symbol` as a registry column rather than a parameter. Rejected — adds schema divergence for no gain; treating `symbol` as just another parameter keeps one code path.

**2. Hand-curate the registry as a Python dict, emit JSON + SQLite.**
akshare's registry is scraped/generated upstream. yfinance's surface is small and stable, so a hand-curated dict in `core/seed.py` (categories, descriptions, params, representative output columns) is the source of truth; a `migrate_registry.py` mirrors it into SQLite, exactly mirroring akshare's `core/migrate_registry.py` + `metadata/registry.db` split. This keeps the two-table schema identical and avoids building a yfinance-docs scraper (YAGNI).
- *Alternative*: introspect `yf.Ticker` methods at runtime. Rejected — yields no descriptions/categories/columns, which are the whole point of the registry.

**3. Reuse akshare's `models.py` / `database.py` / `registry.py` shapes verbatim, renamed.**
The `Function`/`FunctionColumn` models, the `Database` singleton (env var `YFINANCE_DATABASE_URL`, default `metadata/registry.db`), and the `RegistryService` + module-level convenience API are copied and namespaced to `cli_anything.yfinance`. This is deliberate duplication, not a shared base — matches the repo's existing convention (each harness owns its copy; the shared `mcp/models/` package is for MCP-domain tables, not harness registries).

**4. MCP server copies `akshare-mcp/server.py` almost verbatim.**
Same five tools, same `_serialize_result` (DataFrame/Series/dict/list/scalar), same `importlib.import_module("yfinance")` execution path. The only structural change is the runner dispatch for `ticker_*` vs top-level (decision 1). Registered in `.mcp.json` with the `uv run --directory ... python server.py` form used by `cron-mcp` (avoids a pre-built venv path).

**5. Skip the proxy module.**
akshare's `proxy.py` solves a China-network-specific problem yfinance doesn't have. Omitting it is the lazy-correct call; the CLI's `proxy` subcommand group is also omitted.

## Risks / Trade-offs

- **[yfinance rate-limiting / Yahoo blocking automated calls]** → yfinance already retries and caches internally; document in the harness README that heavy use may hit Yahoo limits. No app-level retry layer (YAGNI until observed).
- **[yfinance API drift — methods renamed/removed upstream]** → curated registry is small and manually maintained; a skipped test (`@pytest.mark.skipif`) guards the live `call` path. Broken methods surface as runtime errors from `call_yfinance_function`, same as akshare.
- **[Schema duplication with akshare harness]** → accepted; matches repo convention. If a third harness appears, extract a shared base then — not now.
- **[`ticker_*` naming is a convention, not enforced]** → document it in the runner; the dispatch key is the `ticker_` prefix. A name without that prefix is treated as a top-level `yf.<name>`.
- **[Output-column metadata is representative, not exhaustive]** → yfinance returns wide, sometimes nested DataFrames; we record the key columns, not every one. Marked with `ponytail:` comment in the seed.

## Migration Plan

Purely additive — no migration of existing data. Rollout:
1. Add `yfinance-agent-harness/`, install editable, run `migrate_registry.py` to build `metadata/registry.db`, run tests.
2. Add `mcp/yfinance-mcp/`, `uv sync`, smoke-test `call_yfinance_function`.
3. Add `.mcp.json` entry.

Rollback: delete the three additions (harness dir, mcp dir, `.mcp.json` entry). No shared state touched.
